สร้างเว็บแอพ • ขั้น 1

Prompt P1 — สั่งสร้างแอพทั้งตัวด้วยข้อความเดียว

สร้างเว็บแอพชื่อ ReceiptAI ให้ฉัน ด้วย Python + Streamlit ไฟล์เดียวชื่อ app.py
1. หน้าเว็บภาษาไทย โทนสีน้ำเงินเข้ม มี sidebar: อัปโหลดใบเสร็จ / ประวัติ / ตั้งค่า
2. อัปโหลดรูปได้ทั้งลากวางและเลือกไฟล์ รองรับ JPG, PNG, PDF แสดงภาพตัวอย่างทันที
3. ปุ่ม "อ่านด้วย Hermes AI" ส่งรูปผ่านฟังก์ชัน extract_receipt(image_bytes)
   โดยอ่าน Token จาก environment variable LITELLM_ADMIN_KEY เท่านั้น ห้าม hardcode
4. ผลลัพธ์เป็น JSON แสดงเป็น: การ์ดสรุป + ตารางสินค้า + ตรวจเลขคณิตเทียบยอดรวม
5. มีปุ่มดาวน์โหลด JSON และ CSV และเก็บประวัติการอ่านใน session
6. มีโหมดสำรอง MOCK_MODE ถ้าไม่มี Token ให้ใช้ข้อมูลตัวอย่างและขึ้นป้าย "โหมดสาธิต"
7. ใส่คอมเมนต์ภาษาไทยสั้น ๆ ทุกฟังก์ชัน ให้คนไม่เคยเขียนโปรแกรมอ่านรู้เรื่อง

📄 Prompt ฉบับเต็มอยู่ในไฟล์แจก 02-prompts.md — ก๊อปวางได้เลย ไม่ต้องพิมพ์เอง

สร้างเว็บแอพ • ขั้น 1

ทำไม Prompt นี้ถึงเวิร์ก

  • บอกเครื่องมือชัด: Streamlit ไฟล์เดียว = ง่ายสุดสำหรับมือใหม่ แก้ไขง่าย
  • บอกหน้าตาเป็นชิ้น ๆ: sidebar, ปุ่ม, การ์ด, ตาราง — AI ไม่ต้องเดา
  • แยกฟังก์ชันอ่านใบเสร็จไว้ต่างหาก: วันหลังเปลี่ยนวิธีอ่าน แก้จุดเดียว
  • Token อยู่นอกโค้ด: โค้ดแชร์ให้ใครก็ปลอดภัย Token ไม่หลุด
  • มีโหมดสาธิตสำรอง: ต่อ AI ไม่ได้ก็ยังเรียนต่อได้ หน้าเว็บไม่ตายกลางคลาส
⚠️ กฎเหล็กบนจอแชร์: ห้ามโชว์ Token จริง — ใช้ placeholder <LITELLM_ADMIN_KEY> เสมอ
สร้างเว็บแอพ • ขั้น 2

สั่งรันแอพ แล้วเปิดเว็บของตัวเอง

export LITELLM_ADMIN_KEY=<LITELLM_ADMIN_KEY>
streamlit run app.py --server.port 8501 --server.address 0.0.0.0
  • เปิดเว็บที่ http://<IP ของเครื่อง A1>:8501
  • ถ้าเปิดไม่ติด ให้เช็กก่อนว่า Security List เปิดพอร์ต 8501 แล้วหรือยัง (สาเหตุอันดับ 1)
  • ปิด terminal = แอพดับ เป็นเรื่องปกติของขั้นทดลอง — วิธีทำให้รันถาวรอยู่ในการบ้านท้ายคลาส
✅ จุดเช็ก 2: เปิดเว็บของตัวเอง เห็นหน้า ReceiptAI แล้ว
สร้างเว็บแอพ • ขั้น 3

Extraction Prompt — หัวใจของการอ่านใบเสร็จ

คุณคือระบบอ่านใบเสร็จรับเงินภาษาไทย จงอ่านรูปใบเสร็จและตอบเป็น JSON อย่างเดียว
ห้ามมีข้อความอื่น ใช้ field: store_name, receipt_date, items[], subtotal,
discount, vat, total, payment_method, confidence

กฎการอ่าน:
- ตัวเลขทุกช่องเป็น number ไม่มี "," และไม่มีสัญลักษณ์ ฿
- วันที่: ปีในใบเสร็จเป็น พ.ศ. ให้แปลงเป็น ค.ศ. (YYYY-MM-DD)
- ช่องไหนอ่านไม่ออกให้ใส่ null และลด confidence — ห้ามเดายอดเงินเด็ดขาด
- total = ยอดที่ลูกค้าจ่ายจริง หลังหักส่วนลดและรวม VAT แล้ว
- ถ้ารูปไม่ใช่ใบเสร็จ ให้ตอบ {"error": "not_a_receipt", "confidence": 0}

Prompt นี้อยู่ในฟังก์ชัน extract_receipt() — อยากอ่านเอกสารชนิดอื่น เปลี่ยนแค่ชุดนี้ (ท้ายคลาสจะโชว์)

ทดสอบ • ตรวจทานผล

กฎทองของคืนนี้: AI อ่านให้ แต่คนตรวจยอดรวมเสมอ

  • เช็กที่ 1: ผลรวมรายการสินค้า ต้องเท่ากับยอดรวมบนใบ (แอพของเราตรวจให้อัตโนมัติ ไม่ตรง = แถบแดง)
  • เช็กที่ 2: ดู confidence — สูงไม่ได้แปลว่าถูกเสมอ แต่ต่ำแปลว่าต้องระวังเสมอ
  • เช็กที่ 3: วันที่ต้องเป็น ค.ศ. และยอดต้องไม่มีจุลภาคปน ไม่งั้นเอาเข้า Excel พัง
✅ จุดเช็ก 3: อ่านใบเสร็จของตัวเองสำเร็จอย่างน้อย 1 ใบ และยอดรวมตรง
ทดสอบ • เมื่อผลอ่านผิด

อ่านผิดไม่ใช่จุดจบ — ใช้ Prompt P3 สั่งแก้

ผลการอ่านใบเสร็จใบนี้ผิด: ยอดรวมที่ถูกต้องคือ <ยอดจริง> แต่ AI อ่านได้ <ยอดที่ผิด>
จงแก้ Extraction Prompt ใน app.py โดย:
1. ย้ำให้อ่านบรรทัด "ยอดรวม/จำนวนเงินทั้งสิ้น" เป็นหลัก ไม่ใช่ยอดก่อนหักส่วนลด
2. สั่งให้ไล่อ่านรายการสินค้าทุกบรรทัด ห้ามรวมหลายรายการเป็นบรรทัดเดียว
3. เพิ่มกฎ: ถ้าผลรวมรายการไม่เท่ายอดรวม ให้อ่านซ้ำอีกรอบก่อนตอบ
แสดงเฉพาะส่วนที่แก้ และอธิบายเป็นภาษาไทยสั้น ๆ ว่าแก้เพราะอะไร

หลักการ: อย่าสั่งแค่ว่า "อ่านให้ถูก" — ต้องบอกว่าใบที่แล้วพลาดตรงไหน AI ถึงจะแก้ตรงจุด

โดยเปลี่ยนเฉพาะ Extraction Prompt ให้ดึง field เหล่านี้เพิ่ม:
เลขประจำตัวผู้เสียภาษีผู้ขาย/ผู้ซื้อ, เลขที่ใบกำกับ, มูลค่าก่อน VAT, VAT 7%, ยอดรวม

ใช้งานจริง • ความปลอดภัย

ก่อนเอาไปใช้จริง เช็ก 4 ข้อนี้

  • Token คือกุญแจบ้าน: เก็บใน env var / ไฟล์ .env เท่านั้น ห้ามอยู่ในโค้ด ห้ามส่งให้ใคร
  • พอร์ตที่เปิดคือประตู: เปิดเฉพาะที่จำเป็น และรู้ตัวเสมอว่าเปิดอะไรไว้บ้าง
  • ใบเสร็จลูกค้า = ข้อมูลส่วนบุคคล: มีชื่อ/เลขสมาชิก/ท้ายเลขบัตรได้ — ระวังการเก็บและแชร์ต่อ
  • อยู่ในโควตา Always Free: ตรวจ Budget Alert เป็นระยะ ค่าใช้จ่ายจะได้ไม่หลุดโดยไม่รู้ตัว
